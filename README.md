## 会员车型偏好

使用同一批235,674条有效骑行。组内占比 = 本会员类型使用某车型的骑行次数 ÷ 本会员类型全部骑行次数。每个群体内部占比合计100%，不以全网骑行量为分母。

| 会员类型 | 电动车次数 | 电动车占比 | 普通自行车次数 | 普通车占比 | 合计 |
|---|---:|---:|---:|---:|---:|
| 非会员 casual | 34,083 | 55.92% | 26,865 | 44.08% | 60,948 |
| 会员 member | 86,071 | 49.26% | 88,655 | 50.74% | 174,726 |

非会员电动车组内占比比会员高6.66个百分点。会员两类车型使用较均衡，普通车略多。统计单位是骑行次数，不是独立用户人数；价格、车辆可用性和电量可能影响选择，不能认定个人主观偏好或因果关系，也不能直接替代单站补收车型比例。

`output/user_vehicle_preference.csv`保留原始次数、组内总数`membership_total`及0—1范围的组内占比`within_membership_share`。未发生的组合补零，无样本群体的占比留空；缺失类别显式记为`unknown`以保留分母。`output/user_vehicle_profile.csv`继续提供原始交叉次数，图像为`output/figures/09_membership_vehicle_preference.png`。

## 统计口径

活动量 = 流出 + 流入，适用于比较巡查、引导和停车秩序维护工作量。同一骑行的每个端点各算一次，站点活动量不是独立骑行次数。管理权重以这15站合计活动量为分母，不代表全市警力占比。

净流出 = 流出 − 流入。正值代表补车压力，负值代表回收压力。起点事件按开始时间、终点事件按结束时间归属。站点统计仅保留2024年1月的已知端点；一端缺失不排除另一端，同一站点编号只对应一行汇总。1月出发样本不能覆盖12月出发、1月结束的跨月骑行。

日类型包括全月31天、周一至周五23天、周末8天；“工作日”仅指日历分类，未调整节假日。无骑行的日期与小时补零后再计算日均值。月累计量不等于某一天应调度的车辆数。

分车型调度先计算同站、同日类型、同时间窗口的净流出，再分别计算正方向的补车比例和负方向的回收比例。不能用电动车与普通车的绝对净流量混合计算一个比例；没有该方向压力时比例为空。窗口内的变化可能相互抵消，应结合逐小时明细检查。

这些数据只描述已完成骑行，没有实时库存、站点容量、人工搬运或未满足的需求，不能据此确认缺车/满桩或宣称调度最优。

## 输出数据

| 文件 | 含义 |
|---|---|
| top_station_activity.csv | 前15站排名、名称、总活动量、日均活动量、管理权重和高峰小时 |
| top_station_hourly_flow.csv | 分日类型的站点×小时流入、流出、净流出及日均值 |
| top_station_daily_flow.csv | 站点逐日实际计数 |
| top_station_vehicle_flow.csv | 站点×车型的月累计流量 |
| top_station_hourly_vehicle.csv | 日类型×站点×小时×车型的累计量和日均值 |
| top_station_date_hour_vehicle.csv | 15站×31天×24小时×2车型，共22,320行精确计数 |
| top_station_dispatch_windows.csv | 00—07、07—10、10—16、16—20、20—24时的车型补车/回收比例 |
| station_analysis_summary.json | 端点口径、跨月排除数、站点数量与覆盖率 |

所有CSV采用UTF-8 BOM编码。`departures`为流出，`arrivals`为流入，`total_activity`为两者之和，`net_outflow`为两者之差，`*_per_day`为对应日类型的日均值。比例列取值0—1，无需该方向调度时留空。
